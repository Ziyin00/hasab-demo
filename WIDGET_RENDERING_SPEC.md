# Hasab Chatbot Widget — Rendering Spec (`hasab-chatbot.js`)

Spec for the CDN script served from `https://api.hasab.ai/widget/v1/hasab-chatbot.js`, the
script actually embedded on customer sites via the snippet generated by the Chatbot Widgets
dashboard. The reference implementation for correct visual/behavioral output is
`ChatWidget.tsx` in the `hasab-demo` dashboard repo (used there for widget testing/preview) —
this doc describes what that reference does, so the CDN script can match it exactly.

**Why this matters:** the dashboard lets an admin fully configure a widget's appearance and
behavior. The embed snippet carries that configuration verbatim. If the script doesn't honor
every field below, what a customer sees on their site won't match what was configured in the
dashboard — which is the core guarantee this widget system is supposed to provide.

## Confirmed repro (latest live test)

Tested by embedding the exact snippet below on a live page. The widget loaded and the visitor
session worked, but the icon-fallback behavior required in §4.5–4.7 is not implemented —
these three elements render literal English words instead of icons, even though nothing in

| Mic button | `mic.label: null`, `mic.icon_url: null` | Icon only | Renders the literal text **"Mic"** |
| Send button | `send.label: null`, `send.icon_url: null` | Icon only | Renders the literal text **"Send"** |

Everything that isn't an icon-vs-text fallback is already working.

## 1. Data attributes on the `<script>` tag

```html
<script
  async
  src="https://api.hasab.ai/widget/v1/hasab-chatbot.js"
  data-widget-id="wgt_xxxxxxxxxxxxxxxxxxxx"
  data-position="bottom-right"
  data-default-language="en"
  data-welcome-message="Hi, how can I help?"
  data-theme='{...}'
  data-settings='{...}'
></script>
```

| Attribute | Type | Notes |
|---|---|---|
| `data-widget-id` | string | Public identifier. Used to create a short-lived visitor session token and resolve the widget's chat contexts/RAG stores. |
| `data-position` | `"bottom-right"` \| `"bottom-left"` \| `"top-right"` \| `"top-left"` | Which corner the launcher + panel dock to. |
| `data-default-language` | string | Initial selected language code (matches a `code` in `data-settings.languages`). |
| `data-welcome-message` | string | Shown in the empty-state panel before any message is sent. |
| `data-theme` | JSON string | See §2. |
| `data-settings` | JSON string | See §3. |

All fields are optional/nullable except `data-widget-id`. Treat missing/null as "use a sane
built-in default" — never throw or leave a blank space where content should be.

## 2. `data-theme` shape

```ts
{
  primary_color?: string;
  panel_background?: string;
  message_area_background?: string;
  text_color?: string;
  bot_message_background?: string;
  bot_message_text_color?: string;
  user_message_background?: string;
  user_message_text_color?: string;
  chip_background?: string;
  chip_text_color?: string;
  border_color?: string;
  font_family?: string;
  border_radius?: string;      // e.g. "18px"
  panel_width?: string;        // e.g. "400px"
  panel_height?: string;       // e.g. "580px"
  launcher_size?: string;      // e.g. "64px"
  launcher?: {
    type?: "text" | "icon";
    label?: string;
    icon_url?: string | null;
    background_color?: string;
    text_color?: string;
  };
  header?: {
    avatar_url?: string | null;
    avatar_initials?: string;
  };
  mic?: {
    label?: string;                        // idle-state caption (status strip only, see §4.5)
    recording_label?: string;              // recording-state caption
    processing_label?: string;             // processing-state caption
    icon_url?: string | null;              // idle icon override
    recording_icon_url?: string | null;    // recording icon override
    background_color?: string;             // idle button background
    recording_background_color?: string;   // recording button background
    processing_background_color?: string;  // processing button background
    text_color?: string;                   // icon/text color on the button
  };
  send?: {
    label?: string;
    icon_url?: string | null;
  };
}
```

## 3. `data-settings` shape

```ts
{
  title?: string;                 // header bot name
  subtitle?: string;               // header status line (e.g. "Ready to help")
  launcher_label?: string;          // fallback for launcher.label if theme.launcher.label unset
  input_placeholder?: string;
  show_language_selector?: boolean;
  languages?: { code: string; label: string }[];
  quick_prompts?: { label: string; prompt: string }[];
  features?: {
    audio_upload?: boolean;
    quick_prompts?: boolean;
    language_selector?: boolean;
  };
}
```

## 4. Required rendering behavior

### 4.1 Header
- Avatar: `header.avatar_url` image if set → else `header.avatar_initials` text → else a
  default bot icon. Never blank.
- Title: `settings.title`. Subtitle: `settings.subtitle`.
- Online-status dot is decorative (green, always "online") — not driven by any field.

### 4.2 Language selector
- Populate the dropdown **from `settings.languages`** (`code` + `label` pairs) — do not use a
  hardcoded language list.
- Hide entirely if `settings.features.language_selector === false` or
  `settings.show_language_selector === false`.
- Initial selection = `data-default-language`; persists to the visitor's session/localStorage
  after they change it.
- When the visitor picks a language not in your fully-translated set, still switch the UI
  language code and send a generated instruction to the backend like
  `"CRITICAL: You MUST respond ONLY in {label}."` using the language's configured `label` —
  don't silently ignore unknown codes.

### 4.3 Quick-prompts / FAQ strip
- Render **only** from `settings.quick_prompts` (`label` shown on the chip, `prompt` sent as
  the message when clicked).
- Only show when the array is **non-empty** and `settings.features.quick_prompts !== false`.
- Only visible before the first message is sent (empty-state only).
- **An empty `quick_prompts` array means show nothing.** This is correct behavior, not a bug —
  don't invent placeholder prompts when the array is empty.

### 4.4 Welcome / empty state
- Show a centered icon + `data-welcome-message` only. No extra hardcoded heading text (e.g. no
  literal word "Welcome" above it) — the message itself is the whole content.

### 4.5 Mic button — **icon only, never bare text**
This is the most visible bug in the current script: it currently renders the literal word
"Mic" as button content. It must render an **icon**, with three states:

| State | Background | Icon |
|---|---|---|
| idle | `mic.background_color` | `mic.icon_url` image, else a mic glyph |
| recording | `mic.recording_background_color` | `mic.recording_icon_url` image, else a stop/square glyph |
| processing | `mic.processing_background_color` | a spinner |

- Icon/text color on the button = `mic.text_color`.
- The `label`/`recording_label`/`processing_label` fields are **not** button content — they're
  the caption text in the status strip shown above the input row while recording/processing
  (e.g. "{processing_label}" instead of a hardcoded "Transcribing audio…"). The button itself
  stays icon-only regardless of these fields.
- Hide the mic button entirely if `settings.features.audio_upload !== true`.

### 4.6 Send button — icon by default, label optional
This is the second most visible bug: it currently renders the literal word "Send" with no
icon at all.
- Default: render `send.icon_url` image if set, else a paper-plane glyph.
- Only render `send.label` as visible text **next to** the icon if it's a non-empty string —
  never replace the icon with bare text.

### 4.7 Launcher (closed-state bubble)
- If `launcher.icon_url` is set, use that image.
- Else if `launcher.type === "text"`, show a small icon **plus** `launcher.label` /
  `settings.launcher_label` text together (icon-only buttons should never silently become
  text-only).
- Else, show a default chat-bubble icon.
- Background = `launcher.background_color`, icon/text color = `launcher.text_color`.
- Size = `launcher_size`. Dock corner = `data-position`.

### 4.8 Message bubbles
- User messages: `user_message_background` / `user_message_text_color`.
- Bot messages: `bot_message_background` / `bot_message_text_color`, `border_color` border.
- Panel chrome: `panel_background`, `message_area_background`, `text_color`, `font_family`,
  `border_radius`, `panel_width`, `panel_height`.

## 5. Known functional bug (not styling)

**"Invalid or expired widget session" is being rendered as if it were a bot chat message**,
and it's recurring on every send in the same conversation (observed 3× in one session in
testing). This means the visitor session-token flow is failing repeatedly — likely one of:
- token creation failing for this `widget_id`,
- a token expiry/refresh bug (token dies mid-conversation and never gets renewed),
- an allowed-origins / CORS mismatch causing the backend to reject the request outright.

This needs server-side log investigation on whatever service issues/validates these tokens —
it's independent of the rendering fixes above, and should be root-caused before or alongside
the UI fixes, since a broken session makes the whole widget nonfunctional regardless of how
it looks.
